## 1. 今天要掌握的问题：页面之间怎么切换

### 1.1 三种可选方式

| 方式 | 地址形态 | 谁在管历史与地址栏 | 引入成本 |
| --- | --- | --- | --- |
| **多页面 MPA + 查询参数** | `news.html?cat=足球` | 浏览器原生 | 0（本项目已在用） |
| 前端路由 SPA（hash） | `index.html#/news/足球` | 自己写 JS 监听 hashchange | 中：需把现有 5 页揉进 1 页，返工大 |
| 前端路由 SPA（History API / 路由库） | `/news/足球` | 自己拦截点击 + 处理前进后退 | 高：需引入库或手写拦截，属「路由库进阶用法」 |

### 1.2 本项目的选择：多页面 MPA + 查询参数

**结论：沿用现有做法，不引入路由库。**

现状已在用这套：`league.html?lg=nba`、`league.html?lg=cba` 等四个联赛页共用一个 HTML，靠查询参数区分。

**选它的四条理由**

1. **地址栏天然带状态**——`news.html?cat=足球` 复制给别人能打开同一页，刷新不丢状态；
2. **前进/后退零成本**——浏览器原生行为，不用自己维护 history 栈；
3. **零迁移风险**——照抄 `league.html?lg=` 的既有模式，不动现有 5 个页面；
4. **对齐今日边界**——清单明确「路由库的进阶用法：够用就好」，MPA 正好够用。

**代价（如实记录）**

- 每次切换会整页重新加载，有轻微白闪；
- 跨页共享状态只能靠 localStorage（本项目 `hot-theme` 主题键就是这么做的）；
- 地址栏参数可见，语义不如 `/news/足球` 好看。

### 1.3 为什么不用 `/news/:category` 这种路径参数

清单给的 `/news/:category`、`/news/detail/:id` 属于**路径参数式路由**（Express / React Router 风格），需要服务端把 `/news/足球` 重写回某个 HTML 文件。本项目托管在 **GitHub Pages 纯静态站，没有服务端重写能力**——直接访问 `news/足球` 会 404。

若要硬做，必须在 `404.html` 里写 JS 跳转来模拟，这正属于今日「不做」的路由进阶用法。

**处理**：以查询参数实现，并在页脚注明「对应设计稿的 `/news/:category`」。**切换机制本身完全相同**（URL 带状态 + 浏览器管历史），第 3 周若上线短路径，只换链接写法、不返工逻辑。

### 3.1 V2 赛事列表页 `news.html?cat=足球`

| 状态 | 触发条件 | 页面表现 | 主文案 | 副文案 / 按钮 |
| --- | --- | --- | --- | --- |
| **加载中** | 刚进页面 / 切换分类 | 3 张骨架屏卡片（脉冲动画） | —（`aria-live` 播报「正在加载足球资讯」） | — |

| **空** | 该分类下 0 条已发布条目 | 🈳 空态框 | **该分类暂无资讯** | 「换个分类看看，或明天再来。」 |
| **错误** | fetch 失败 / 解析失败 / HTTP 非 200 | 📡 空态框 | **资讯加载失败，请检查网络后重试。** | 按钮「重新加载」 |

### 5.2 处理方式

**在不违反以上约束的前提下满足今日需求**：

- V3 详情页**只做「单条速览的完整呈现」**——把 `data/news.json` 里该条的已有字段（标题、摘要、板块、联赛、来源名称、来源链接、速览日期）完整铺开，比列表卡片多出「板块归属」「速览日期」「来源链接」三处信息，并补同联赛相关条目推荐；
- **不新增 `content` / 正文类字段**，不采集也不存储原文段落；
- 完整内容仍通过「**查看原文**」按钮跳转外部来源，与 PRD 第 9.1 节的合规策略一致；
- 这样 V3 满足「可独立访问的第三个视图」与「展示某条体坛新闻的完整图文内容」中**「该条目的完整信息」**这一层，同时守住「不转载正文」的合规红线。

**结论**：本规划属于「在既有约束内新增一个视图」，不改变 PRD 的产品定位与合规策略。**建议**在 PRD 第 5 节加一行注记对齐（待确认项第 5 条）；在你确认前，**不改 PRD.md**。
