## 0. 今天要回答的问题

> **同伴卡在哪一步？这一步你自己为什么没发现？**

这份清单里的每条规则，都是为了让你能回答这一个问题。如果测完你答不出来，那这次测试就等于没做。

**先记住一句话**：今天不是去证明「我的页面好用」，而是去收集「别人在哪里停下来」。他卡住是收获，不是丢脸。

---

## 1. 三条铁律（违反任何一条，这次测试的价值就没了）

| # | 铁律              | 具体怎么做                                  |
| - | --------------- | -------------------------------------- |
| 1 | **不解释、不指路、不示范** | 他问「这个在哪」→ 你回「你按你的理解找找看」。**别说「点右上角」**   |
| 2 | **10 秒规则**      | 他停住后先在心里数 10 秒，再决定要不要救。你救得越早，你越学不到东西   |
| 3 | **记原话，不记结论**    | 写「他说：这啥意思？」比写「他没看懂」有价值十倍。原话能让你事后复现他的想法 |

> 你在测试中的角色只有一个：**他操作时闭嘴，他说话时记下来。**

---

## 2. 开场白（照读，约 30 秒）

> 「我在做一个体育资讯的小页面，想请你帮我看看。等下我给你几个小任务，你随便点，怎么顺手怎么来。**没有对错，卡住了很正常** —— 你卡住的地方对我最有价值。你操作的时候我不说话，做完我记一下就行。」

念完先交代三件事，不然他会一直反问你：

1. 不用装任何东西，手机浏览器打开一个网址就行；
2. 只能在他这台设备上自己操作，你不给他指；
3. 全程大概 15 分钟。

---

## 3. 五条任务（一条一条给，念完等他做完，再念下一条）

| #  | 念给对方的话（**原样念**）                            | 你心里在测什么（❌ **不要念出来**）             |
| -- | ------------------------------------------ | -------------------------------- |
| T1 | 这个页面，你用一句话告诉我它是干嘛的。                        | 首屏能不能自己说清楚自己是什么                  |
| T2 | 帮我把界面换成浅色的。                                | 主题切换按钮（☀️）能不能被主动发现               |
| T3 | 这个站里有比赛信息。帮我找一下**昨天开赛最晚**的那场比赛，告诉我是谁打谁。    | 「昨天/今天/明天」日期切换能不能被发现；当天没数据时会怎样   |
| T4 | 看看 NBA 现在排第一的是哪支队，赢了几场？                    | 联赛页的子 Tab（排行）能不能找到               |
| T5 | 帮我找一条**关于湖人队**的资讯，打开看看它的完整内容，然后**回到资讯列表**。 | 三级跳：导航「资讯」入口 → 分类切换 → 详情页 → 返回路径 |

**标准答案**（你心里有数就行，**别说出来**）：

| 任务 | 答案                                              |
| -- | ----------------------------------------------- |
| T3 | 英超 **曼联 vs 阿森纳**（昨天 22:00）                      |
| T4 | **凯尔特人**，3 胜 0 负                                |
| T5 | 篮球分类里的「湖人客场112比108击败凯尔特人」；详情页应有「查看原文」外链和同联赛相关条目 |

> **T3 的一个提醒**：示例数据里**今天（10-02）没有比赛**，所以他点进赛程页很可能先看到「当日无重点赛事」。他接下来是自己找到日期切换、还是直接说「这页没东西」，**是今天最有价值的观察点之一 —— 别提示他。**

### 4.3 复盘三问（今天的学习点，必须填）

**复盘 1 · 他卡在哪一步？**  
（写最卡的那**一处**，别写一堆）

> 没有明显卡顿，主要在主页各栏目来回查看，寻找需要的入口

**复盘 2 · 这一步我当时为什么没发现？**  
（提示：你天天用这页，你知道「路」；他手上只有任务，没有地图。是不是「做了但没入口」「入口有但不像能点」「像能点但位置在视线之外」？）

> 用户没有一眼找到目标入口，所以需要先查看不同栏目

**复盘 3 · 我原来假设他会在哪里找？这个假设错在哪？**  
（把你写这页时的想法写出来，再对照他实际的动作）

> 原来假设用户会直接进入某个固定栏目，但实际用户会先在主页多个入口之间来回确认。
>
> 说明用户不是一开始就明确目标位置，而是需要通过浏览和判断来找到入口。

## 7. 板块③ · 最小修复记录（Day 14）

**只改了 1 处**：≤480px 顶部导航从「横向滑动（滚动条隐藏）」改为「允许换行，七个入口全部可见」。

| 项 | 内容 |
| -- | ---- |
| 依据 | 复盘 2/3：测试者在主页多个入口来回确认、没有一眼找到目标入口；代码核对发现 ≤480px 时 `.nav-pages` 横向滑动且滚动条被刻意隐藏，欧冠/英超等右侧入口**无任何提示地被裁掉** |
| 改动 | `css/style.css` + `css/home.css` 同一条 ≤480px 规则（同一逻辑处，两文件各一份） |
| 验证 | ✅ **手机实测通过（22:47 截图）**：导航换行两行，七个入口全部可见；局域网 200 + 新 CSS 确认下发 |

**记下但今天不改**（守住「不一口气全改」）：

- T4 测试者答「3 胜 1 负」（实际 3 胜 0 负）：NBA 排行表 `min-width: 420px` 在 375px 手机上必然横向溢出约 77px，右侧「净胜/胜率」列需滑动才能看全，容易看串列。→ 留给 Day 15 候选。

**复盘三问的最终答案**（对照板块② 记录修正）：

1. **他卡在哪一步**：找不到 NBA/欧冠等联赛入口 —— 因为在手机上这些入口被横向滑动藏住了，且滚动条不可见。
2. **我为什么没发现**：我一直在电脑浏览器验收（≥640px 布局，导航一排全放得下），从未在手机宽度看过自己的页面。
3. **原假设错在哪**：我以为「横向滑动是常规手机模式，大家都会滑」；实际是隐藏滚动条让它看起来像「没有更多内容」。

## 附录 A · 找不到人时的降级方案（清单给的兜底）

自己**间隔 10 分钟**，按第 3 节的同一份清单重新操作一遍，记录**第一次找不到的地方**。

⚠️ 这不是真人测试。记录里**必须标明「本人自测（降级）」**，不能冒充同伴测试 —— 你已经知道路，价值天然低于真人。

## 附录 B · 余力加练：手机宽度复测

主任务完成后，**再测一次手机宽度**：按手机竖屏宽度（约 375px）把 T1–T5 走一遍，重点看两件事：

1. 页面有没有横向溢出 / 需要左右滑才能看全；
2. 按钮和可点区域，指头够不够点（有没有 < 44px 的目标）。

> 手机本来就是这个产品的主场景，但前 13 天你都是拿电脑浏览器验收的 —— 这一遍可能出你最没预料到的问题。
