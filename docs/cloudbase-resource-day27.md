## 6. 导出数据（三种方式，第一种已跑通）

| 方式 | 命令 | 适合 | 局限 |
| ---- | ---- | ---- | ---- |
| **① 脚本全量导出**（推荐，已实测） | `node scripts_cloudbase/export-data.mjs` | 留一份完整快照 | 走接口导出，不是数据库原生 dump |
| ② 单表快查 | `tcb db execute -e <envId> --sql "SELECT count(*) FROM news_items;"` | 核对行数、抽查一行 | 只适合小结果集，不适合整表搬 |
| ③ 控制台 | 云开发控制台 → 数据库 → 导出 | 习惯用可视化的人 | PostgreSQL 环境的导出入口与 MySQL 不同，且同样要扫码登录 |

### 6.1 脚本实测记录（2026-10-14 19:44）

```
node scripts_cloudbase/export-data.mjs
→ 输出目录：db/exports/20261014-194435
  ✓ hot_items            48 /    48 行
  ✓ news_items           17 /    17 行
  ✓ matches              37 /    37 行
  ✓ leagues               4 /     4 行
  ✓ league_schedule    3891 /  3891 行
  ✓ league_standings    162 /   162 行
  ✓ league_players      155 /   155 行
  ✓ league_brackets       7 /     7 行
  ✓ push_log              5 /     5 行
  ✓ subscribers           5 /     5 行
  合计 10 张表 / 4331 行 / 1447.3 KB —— 全部表行数与库内计数一致
```

脚本的几条设计点（都不是随便定的）：

- **走 PostgREST**（和云函数同一条 HTTP 路），因为体验版**不支持 PG 的 TCP 直连**；
- **零依赖**，只用 Node 原生模块，和 `shared/pg.js` 一个路子；
- **行数自校验**：先用 `Prefer: count=exact` 向库要整表总数，再分页拉，最后比对 —— `rows.length === total` 才算成功。**只要有一张表对不上，退出码就是 1，并且明说「这次导出不可信」**（Day 21 的教训：比对脚本不打印「比了多少条」，就会输出「0==0==0 完全一致」的假结论）；
- **密钥只读不打印**：从 `.env` 或环境变量读，终端只输出「有 / 长度」，**不输出值**；
- 输出目录 `db/exports/` **已加进 `.gitignore`**（一次约 1.4MB，且是一次性快照，不该进仓库）。
