# 每日体坛速览 · 作业手册

> **这个 Skill 是什么**：本项目已确认前端规则的固化版。它不生产内容，只在每次干活后逐条核对——
> 数据有没有来源、比分战报齐不齐、字号与卡片样式合不合规、窄屏有没有横向滚动。
>
> **上游依据**（冲突时以它们为准，本文件只是摘录与提醒）：
> `PRD.md`（第 4、6、10 节）· `TECH_DESIGN.md`（第 4、7、9 节）· `AGENTS.md`（第八节 项目专属规则）

---

## 一、硬约束（不许违反）

### 1.1 内容范围：主做篮球与足球

- **主打**：篮球（NBA / CBA）、足球（英超 / 中超 / 欧冠）。
- 其他项目（电竞、综合）可入「综合」类，但**不得挤占篮球足球的主要版面**。
- 每条必须给 `league` 标签，取值只能是：`NBA` / `CBA` / `英超` / `中超` / `欧冠` / `电竞` / `综合`。
- 大类映射（前端硬编码，不要改）：
  - 篮球 = NBA / CBA
  - 足球 = 英超 / 中超 / 欧冠
  - 综合 = 电竞及其他

### 1.2 数据必须溯源

- 每条速览必填 `source_name`（来源名称）+ `source_url`（可访问 URL）。
- 每场比赛必填 `data_source`（比分来源），用于核对与更正溯源。
- **比分只信官方数据源**，发布前人工抽查；发现错误当日更正，并更新 `updated_at` 留痕。
- 只保留「标题 + 一句话摘要 + 原文链接」，**不整段转载正文、不存储全文、不做视频/集锦**。
- **未核实使用条款的数据源不得接入**（候选清单见 `TECH_DESIGN.md` 第 12 节，标了"待核实"）。

### 1.3 必须包含比分与战报

- 赛程类条目：**联赛 + 主队 vs 客队 + 开赛时间（精确到分钟，北京时间）+ 比赛状态**，四要素齐全。
- 已结束的比赛必须显示最终比分（`home_score:away_score`），且与官方结果一致。
- 速览的 `summary` 一句话摘要**须含背景/影响/后续之一**，不能只是比分的复述。
- 状态取值只能是：`未开始` / `进行中` / `已结束` / `延期` / `取消`。

### 1.4 字数与条数上限

- `title` ≤ **30 字**；`summary` ≤ **60 字**。
- 每日速览 6–12 条；休赛期/无比赛日允许降至 4 条，**但不允许断更**（「今日暂无」也是诚实的内容状态）。
- 超限时优先砍「热议」板块，保「头条 / 转会伤病 / 明日看点」。
- 每天每用户至多 1 封推送，无营销内容。

## 二、内容抓取（契约式）

> 本节只定**规则与产出契约**，**不写死具体网站**——真实数据源须先核实条款（1.2 最后一条）才能接入，届时只换数据、不改规则。

### 2.1 抓什么

| 类别 | 产出目标 | 关键字段 |
| --- | --- | --- |
| 文字要闻 | `data/news.json` | `title` / `summary` / `section` / `league` / `source_name` / `source_url` |
| 赛程比分 | `data/matches.json` | `league` / `home_team` / `away_team` / `match_time` / `status` / `home_score` / `away_score` / `data_source` |
| 联赛板块 | `data/{nba,cba,ucl,epl}.json` | 字段统一 camelCase：`teamName` / `wins` / `points` / `playerName` 等 |

### 2.2 优先级与筛选顺序

1. 先取**篮球、足球**的重点赛事（1.1）；
2. 单条内容进哪一类：比分数据归赛程（matches），文字要闻归速览（news），**两者不混**；
3. `section` 四选一：`头条` / `转会伤病` / `热议` / `明日看点`。

### 2.3 抓取节奏

每天三次：早间（收昨晚战报）→ 赛后 → 晚间。页面对用户展示「最近更新时间」。

### 2.4 产出纪律

- 产出即落盘：数据写进 `data/*.json`，不进仓库根目录。
- 录入优先走 `tools/entry.html`（自动生成 id/时间戳、字数校验、查重），不手写字段。
- Skill 只负责**规则**；实际抓取脚本属于后续天的任务，不在此实现。

### 2.5 本地预览（必须走 http，不能双击打开）

- **本机没有 Python**（2026-10-01 确认），起服务用项目自带的 `serve.mjs`：
  项目根目录执行 `node serve.mjs`（默认 8000，可 `node serve.mjs 8080`），或双击 `start-preview.cmd`。
- **铁律**：本项目页面用 `fetch` 读 `data/*.json`，**直接双击 HTML（`file://`）浏览器会拦截本地 JSON 请求**，页面显示「加载失败」——这不是代码 bug，是协议限制。预览一律走 `http://127.0.0.1:端口/`。
- 页面自带「加载失败」提示文案，其中已注明 `file://` 这一原因，便于自查时区分。
- **`.cmd` 启动器必须纯 ASCII**（2026-10-01 踩坑）：Windows cmd 按 GBK 读批处理文件，UTF-8 中文会被拆成乱码并当命令执行，满屏「不是内部或外部命令」。给零的启动器一律只写英文。
- **零的 cmd 里可能没有 node**（WorkBuddy 自带的 node 只在我的 shell 里可用）：`start-preview.cmd` 里已做兜底——`where node` 找不到就改用 `C:\Users\XH\.workbuddy\binaries\node\versions\<版本>\node.exe` 全路径。WorkBuddy 升级后版本号会变，失效时先确认该目录下的实际版本。

## 2.6 验证技巧（踩过的坑，直接复用）

- **测路径穿越防护不能用普通 http 客户端**：`curl` / `http.get` 会在发出请求前自行把 `/../` 折叠掉，请求到不了服务器的防护逻辑，看起来「防护失效」其实是测不到。要用**原始 socket 手写请求行**（`net.connect` → 直接 write `GET /../../../Windows/win.ini HTTP/1.0`）才验得到。
- **判定标准**：正确标准是「**项目目录外的访问是否被拦住**」，不是「某个路径返回 200 还是 403」。`/../AGENTS.md` 规范化后落在项目根内且文件确实存在，返回 200 是正确的。
- **纯前端逻辑的离线验证法**：无浏览器环境时，用 Node **复刻前端的过滤/查找逻辑**跑真实数据，能覆盖大部分分支（分类过滤、草稿不可见、找不到 id、相关推荐为空等），比只做语法检查有效得多。注意复刻要照抄真实代码的判断条件，否则验证的是错的逻辑。
- **更硬的验证：用 `vm` + DOM stub 真跑页面 JS**（2026-10-01 实测有效）。HTTP 200 只证明文件送达，**证明不了 JS 选对了分支**。做法：Node `vm.createContext` 造一个假 `document`（`getElementById` 返回 `{hidden, textContent, innerHTML, dataset, classList, setAttribute, addEventListener}` 的桩对象）+ 假 `location`/`history`/`fetch`/`URLSearchParams`，去掉文件末尾的 `initXXX()` 调用后执行，再手动调 `showState()`/`renderList()` 等函数，断言各状态容器的 `hidden` 是否互斥。这样能真正验到「四种状态每次只有一个显示」。
  - 坑：`.mjs` 是 ES 模块不能用 `require`，临时脚本用 `.cjs` 或 `node -e` 内联。
  - 坑：含正则的检查脚本用 `node -e` 容易被 shell 吃掉转义符，写成临时文件更稳。

## 三、排版样式

### 3.1 字号（下限，不得更小）

| 用途 | 字号 |
| --- | --- |
| 一级标题 h1 | 26px（≥640px 宽屏 30px） |
| 卡片标题 h3 | 15px |
| 正文/摘要 | 13–15px |
| 辅助文字（标签、热度、时间） | **最小 12px，不出现 11px 以下** |

### 3.2 颜色与对比度

- 正文与小字对比度 ≥ **4.5:1**（WCAG AA）；大字（≥18.66px 粗体或 ≥24px）≥ **3:1**。
- 色阶三级：页面底 `--bg` < 卡片 `--card` < 悬浮块 `--chip-bg`；**卡片必须比页面底色亮一级**，列表层次才分明。
- 品牌绿 `#2f7d4f` 只用于按钮底色/强调线，**绿底上的文字必须用白色**。
- 新增颜色先算对比度：深色底用提亮变体、浅色底用加深变体，**深浅两种模式都必须达标**，写进 `:root` 与 `html[data-theme="light"]` 两处。

### 3.3 卡片样式

- 卡片：`--card` 底 + 1px `--border` 边 + 10–14px 圆角 + 12–16px 内边距 + 卡片间距 10–18px。
- 条目标签、热度值、来源名称统一放在卡片内的 meta 行，字号 12px。
- 深浅主题共用同一套变量（`js/theme.js`，localStorage 键 `hot-theme`），**跨页同步，head 内联脚本防闪烁**。
- 标签选中态统一用 `--sel-*` 系列（水滴感浅蓝渐变），覆盖导航当前页 / 日期切换 / 大类筛选 / 联赛子 Tab。

### 3.4 无障碍（余力加练已并入）

- 可点元素必须有键盘可见焦点环（`:focus-visible`）。
- 标签/开关类按钮用 `aria-pressed` 表达状态；切换中的按钮用 `disabled` 并降透明。
- 系统开了「减弱动态效果」时，动画降级为静态（`@media (prefers-reduced-motion: reduce)`）。

## 四、移动端适配

- **基准宽度 375px**：无横向滚动条、无需缩放即可阅读。
- **≤480px**：导航横向滑动（`overflow-x: auto` + `white-space: nowrap`，链接文字禁止内部断行），主题按钮浮到右上角，控件 `padding` 收紧。
- **≤380px**：缩略图 80px → 64px，卡片标题降到 14px。
- 网格/筛选行用 `flex-wrap` 换行而非横向溢出；表格用 `overflow-x` 容器包裹。
- 目标：普通手机网络下首屏 **3 秒内可读**。

## 五、工作流程

1. **取内容** → 按第 2 节契约抓取/整理，落进 `data/*.json`；
2. **核数据** → 逐条对照第 1.2、1.3 节（来源、比分、四要素、字数）；
3. **排版** → 按第 3 节套用现有组件与变量，不新造颜色；
4. **验窄屏** → 按第 4 节在 375px 下过一遍；
5. **自查** → 走完下面第六节清单再交付。

---

## 六、验收清单（做完逐条自查）

- [ ] 全部条目都有 `source_name` + 可访问 `source_url`；比赛都有 `data_source`
- [ ] 篮球、足球是主体，`league` 取值在允许集合内
- [ ] 已结束比赛都有最终比分；赛程四要素齐全；`summary` 含背景/影响/后续之一
- [ ] `title` ≤30 字、`summary` ≤60 字；当日 6–12 条（休赛期 ≥4 条）
- [ ] 无整段转载正文、无视频/集锦内容
- [ ] 辅助文字 ≥12px；新增颜色深浅两模式对比度均达标；卡片比底色亮一级
- [ ] 深色/浅色两套主题都过一遍，切换无跳变
- [ ] 375px 无横向滚动；≤480px 导航不折行不溢出
- [ ] 焦点环可见；`aria-pressed` 状态正确；减弱动效时动画降级
- [ ] 无白屏、无控制台报错
